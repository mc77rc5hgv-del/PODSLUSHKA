# ПОДСЛУШКА ВМЕДА

Telegram-бот принимает предложения в личном чате. Пользователь нажимает «Старт», подписывается на канал и отправляет текст, фото, видео, GIF, файл, стикер или альбом. Подпись, добавленная к медиа в Telegram, входит в ту же заявку. Отдельное текстовое сообщение считается отдельной заявкой.

После отправки материала пользователь выбирает **Анонимно** или **С @username**. Только после этого заявка поступает на модерацию. Бот добавляет ссылку на профиль только при выборе подписи. Черновик можно отменить. Если выбора нет 24 часа, черновик истекает.

В личный чат администратора приходит предпросмотр и карточка с номером заявки, Telegram ID автора, его `@username` при наличии и кнопками **Опубликовать** и **Отклонить**. После одобрения бот сам отправляет материал в канал без отметки о пересылке и без добавления данных автора. Текст, подписи и вложения видны подписчикам в том виде, в котором их прислали. Пользовательские эмодзи Telegram публикуются как соответствующие обычные эмодзи.

В личном чате `/start` открывает главное меню, а `/help` показывает, как отправить разные материалы. Команда `/admin` открывает панель со счётчиками и фильтрами очереди. Нажмите на номер заявки, чтобы открыть её материал и карточку.

Чтобы дать второму аккаунту доступ к обработке заявок, задайте его Telegram ID в `MODERATOR_ID`. После «Старт» он сможет открыть `/admin`, просматривать материалы и принимать решения. Счётчики, данные автора анонимной заявки и команда `/check` доступны основному администратору.

Под публикацией есть две ссылки **ПОДСЛУШКА ВМЕДА** и **Предложить пост**. Обычно это строка в тексте или подписи. Для стикеров, видеокружков и сообщений, в которых уже исчерпан лимит длины, бот прикрепляет кнопки. Для альбома, в подписи которого не хватает места, ссылки идут отдельным сообщением сразу под ним.

## Подключение

1. Создайте бота через [@BotFather](https://t.me/BotFather) командой `/newbot`. В корне проекта скопируйте `.env.example` в `.env` и вставьте токен в `BOT_TOKEN`. `.env` исключён из Git.
2. Установите Node.js 24 или новее и запустите `node src/index.mjs`. В личном чате с ботом нажмите **Старт**, отправьте `/id` и запишите полученное число в `ADMIN_ID`. До подключения канала бот работает в режиме настройки.
3. Добавьте бота в администраторы канала и включите право публиковать сообщения. Для публичного канала укажите его `@username` в `CHANNEL_ID`. Для частного укажите числовой ID вида `-100…` и действующую ссылку-приглашение в `CHANNEL_URL`. Эта ссылка будет видна подписчикам. Для публичного канала бот может определить ссылку автоматически.
4. Перезапустите бота. В личном чате администратора команда `/check` покажет, готов ли бот публиковать. Отправьте пробную заявку, одобрите её и проверьте пост и обе ссылки в канале.

## Постоянная работа

Запускайте бота на постоянно работающем компьютере или сервере. Приложение получает обновления напрямую из Telegram, входящий порт не требуется. Для одного токена запускайте один экземпляр. Если у токена уже настроен webhook, перед запуском нужно переключить его на получение обновлений через `getUpdates`.

`DB_PATH` указывает путь к SQLite-файлу очереди. По умолчанию это `data/submissions.sqlite`. При размещении на сервере храните базу на постоянном диске. База содержит ID авторов и полученные имена пользователей. Материалы незавершённых заявок хранятся в очереди и удаляются из неё после решения.

Если Telegram отклонит отправку, в карточке появится кнопка повтора. Если ответ потеряется во время отправки или процесс остановится в этот момент, карточка попросит проверить, появился ли соответствующий материал в канале. После проверки можно подтвердить доставку или повторить этот шаг. Так бот не дублирует пост при неопределённом результате.

Локальная проверка сценариев с имитацией Telegram API запускается командой `node --test`.

### Cloudflare Workers Free

Worker принимает обновления Telegram по HTTPS, а очередь хранится в [SQLite Durable Object](https://developers.cloudflare.com/durable-objects/platform/pricing/). После каждого нового сообщения Worker планирует проверку очереди. В остальное время он ждёт новых запросов от Telegram.

1. Войдите в Cloudflare с планом **Workers Free**. Из корня репозитория выполните `npx wrangler login` и `npx wrangler deploy`. Wrangler напечатает адрес на `workers.dev`.
2. Через `npx wrangler secret put ИМЯ` задайте `BOT_TOKEN`, `ADMIN_ID`, `CHANNEL_ID` и `WEBHOOK_SECRET`. Для закрытого канала добавьте `CHANNEL_URL`. Для `WEBHOOK_SECRET` сгенерируйте случайное значение, например командой `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`.
3. Вызовите [Telegram Bot API setWebhook](https://core.telegram.org/bots/api#setwebhook). В параметре `url` укажите адрес Worker с окончанием `/telegram`, в `secret_token` передайте значение `WEBHOOK_SECRET`, в `allowed_updates` передайте `["message", "callback_query"]`. Для сохранения порядка обновлений передайте `max_connections: 1`.
4. Отправьте боту `/check` и проверьте публикацию тестовой заявки после одобрения. При переключении обратно на локальный опрос сначала удалите webhook через `deleteWebhook`.

### Northflank Sandbox

[Northflank Sandbox](https://northflank.com/pricing) включает ресурсы для постоянно работающего контейнера и постоянного диска в пределах бесплатного лимита.

1. В [Northflank](https://app.northflank.com/) создайте проект в рабочем пространстве **Sandbox**. Добавьте **Combined service** из этого GitHub-репозитория, ветка `main`. Выберите сборку **Dockerfile**.
2. В разделе **Advanced** подключите [постоянный диск](https://northflank.com/docs/v1/application/databases-and-persistence/add-a-volume) по пути `/data` с режимом **Single Read/Write**. Оставьте одну реплику и уберите порты из настроек сервиса.
3. В **Runtime environment variables** задайте `DB_PATH=/data/submissions.sqlite`, `BOT_TOKEN`, `ADMIN_ID`, `CHANNEL_ID` и при необходимости `CHANNEL_URL`. Токен вводите в панели сервиса. Если вы ещё не знаете свой `ADMIN_ID`, запустите сервис с токеном и отправьте `/id` боту, затем внесите полученное число.
4. Дождитесь запуска контейнера. Отправьте `/check` в личку боту и проверьте публикацию тестовой заявки после одобрения.

### Railway Free

План [Railway Free](https://docs.railway.com/pricing/plans) даёт $1 ресурсов в месяц. Бот использует один контейнер и небольшой диск. Расход отображается в **Workspace → Usage**. Публикация работает, пока сервис запущен и у рабочего пространства есть доступные ресурсы.

1. В [Railway](https://railway.com/dashboard) выберите рабочее пространство с планом Free и создайте проект. Добавьте сервис из этого GitHub-репозитория, ветка `main`. Railway соберёт контейнер по `Dockerfile`.
2. В меню сервиса выберите **Attach Volume** и задайте путь `/data`. Бот создаст базу на этом диске. Для сервиса оставьте одну реплику и выключите **Serverless**, чтобы опрос Telegram работал постоянно.
3. В разделе **Variables** добавьте `BOT_TOKEN` как [секретную переменную](https://docs.railway.com/variables#sealed-variables). После применения изменений бот сможет ответить на `/id` в личном чате. В том же разделе задайте `ADMIN_ID`, `CHANNEL_ID` и при необходимости `CHANNEL_URL`.
4. Включите боту право публиковать в канале, если ещё этого не сделали. В **Deployments** дождитесь статуса **Active**, отправьте `/check` в Telegram и проверьте публикацию тестовой заявки.
