# Подслушка в мида

Telegram-бот принимает предложения в личном чате. Пользователь нажимает «Старт» и отправляет текст, фото, видео, GIF, файл, стикер или альбом. Подпись, добавленная к медиа в Telegram, входит в ту же заявку. Отдельное текстовое сообщение считается отдельной заявкой.

В личный чат администратора приходит предпросмотр и карточка с номером заявки, Telegram ID автора, его `@username` при наличии и кнопками **Опубликовать** и **Отклонить**. После одобрения бот сам отправляет материал в канал без отметки о пересылке и без добавления данных автора. Текст, подписи и вложения видны подписчикам в том виде, в котором их прислали. Пользовательские эмодзи Telegram публикуются как соответствующие обычные эмодзи.

Под публикацией есть две ссылки: **Подслушка в мида** и **Предложить пост**. Обычно это строка в тексте или подписи. Для стикеров, видеокружков и сообщений, в которых уже исчерпан лимит длины, бот прикрепляет кнопки. Для альбома, в подписи которого не хватает места, ссылки идут отдельным сообщением сразу под ним.

## Подключение

1. Создайте бота через [@BotFather](https://t.me/BotFather) командой `/newbot`. В корне проекта скопируйте `.env.example` в `.env` и вставьте токен в `BOT_TOKEN`. `.env` исключён из Git.
2. Установите Node.js 24 или новее и запустите `node src/index.mjs`. В личном чате с ботом нажмите **Старт**, отправьте `/id` и запишите полученное число в `ADMIN_ID`. До подключения канала бот работает в режиме настройки.
3. Добавьте бота в администраторы канала и включите право публиковать сообщения. Для публичного канала укажите его `@username` в `CHANNEL_ID`. Для частного укажите числовой ID вида `-100…` и действующую ссылку-приглашение в `CHANNEL_URL`. Эта ссылка будет видна подписчикам. Для публичного канала бот может определить ссылку автоматически.
4. Перезапустите бота. В личном чате администратора команда `/check` покажет, готов ли бот публиковать. Отправьте пробную заявку, одобрите её и проверьте пост и обе ссылки в канале.

## Постоянная работа

Запускайте бота на постоянно работающем компьютере или сервере. Приложение получает обновления напрямую из Telegram, входящий порт не требуется. Для одного токена запускайте один экземпляр. Если у токена уже настроен webhook, перед запуском нужно переключить его на получение обновлений через `getUpdates`.

`DB_PATH` указывает путь к SQLite-файлу очереди. По умолчанию это `data/submissions.sqlite`. При размещении на сервере храните базу на постоянном диске. База содержит ID авторов и полученные имена пользователей. Материалы незавершённых заявок хранятся в очереди и удаляются из неё после решения.

Если Telegram отклонит отправку, в карточке появится кнопка повтора. Если ответ потеряется во время отправки или процесс остановится в этот момент, карточка попросит проверить, появился ли соответствующий материал в канале. После проверки можно подтвердить доставку или повторить этот шаг. Так бот не дублирует пост при неопределённом результате.

Локальная проверка сценариев с имитацией Telegram API запускается командой `node --test`.

### Railway Free

План [Railway Free](https://docs.railway.com/pricing/plans) даёт $1 ресурсов в месяц. Бот использует один контейнер и небольшой диск. Расход отображается в **Workspace → Usage**. Публикация работает, пока сервис запущен и у рабочего пространства есть доступные ресурсы.

1. В [Railway](https://railway.com/dashboard) выберите рабочее пространство с планом Free и создайте проект. Добавьте сервис из этого GitHub-репозитория, ветка `main`. Railway соберёт контейнер по `Dockerfile`.
2. В меню сервиса выберите **Attach Volume** и задайте путь `/data`. Бот создаст базу на этом диске. Для сервиса оставьте одну реплику и выключите **Serverless**, чтобы опрос Telegram работал постоянно.
3. В разделе **Variables** добавьте `BOT_TOKEN` как [секретную переменную](https://docs.railway.com/variables#sealed-variables). После применения изменений бот сможет ответить на `/id` в личном чате. В том же разделе задайте `ADMIN_ID`, `CHANNEL_ID` и при необходимости `CHANNEL_URL`.
4. Включите боту право публиковать в канале, если ещё этого не сделали. В **Deployments** дождитесь статуса **Active**, отправьте `/check` в Telegram и проверьте публикацию тестовой заявки.
